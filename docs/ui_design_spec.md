# OTR 前端 UI 与交互设计规范

> 本文面向 OTR（`src/`）的前端开发与后续重构，与 [主题接口文档](theme_interface.md)（Token / 钩子 / CSS 白名单）互补：
> `theme_interface.md` 约束**皮肤如何安全地定制外观**，本文约束**组件该如何排版、交互与取舍**。

---

## 1. 核心设计原则

1. **轻盈克制，给主题留呼吸感**：OTR 支持「蓝色大肥鱼」等带整窗背景插画的毛玻璃主题。悬浮条与卡片应紧凑通透，避免厚重的管理后台式大横条遮挡背景。
2. **能对齐的纵线必须对齐**：同屏相邻卡片、跨行进度条的左右边缘要保持同一套网格基准，不因某个卡片数据较多而破坏整页节奏。
3. **不加无增量信息的“废话文案”**：不在界面上为了填补空白而硬塞实现细节或重复说明（例如已有 3 列模型池时，左侧不再写「本机服务 · 3 个模型池」这类说明文本）。
4. **桌面端原生感，禁止原生浏览器弹窗**：所有确认框、下拉菜单都必须跟随应用主题变量，不出现 Windows/macOS 白底原生弹窗割裂感。
5. **同一规范区分「已落地基线」与「重构目标」**：涉及历史遗留结构（如 `window.confirm`、设置页单文件过长、多池卡片嵌套列）时，新写代码与重构均按本文目标规范执行。

---

## 2. 窗口与顶栏（`App.tsx` / `WindowControls.tsx`）

- **窗口基准**：默认 `1080 × 700`，最小尺寸 `860 × 560`（`src-tauri/tauri.conf.json`）。所有排版必须在 `860px` 宽度下不折行错乱、不截断关键数值。
- **平台适配**：无边框窗口在 Windows 显示自绘 `WindowControls`，macOS（`isMacPlatform()`）交还给系统红绿灯，并在顶栏左侧预留避让边距（`pl-[5.25rem]`）。
- **动作与导航分离（重构规范）**：
  - 顶栏右侧的**瞬时动作**（如「刷新」）与**视图切换**（`概览 / 额度 / 设置`）必须以间距或细分割线隔开，不得混进同一个 `segmented` 胶囊。
  - 视图切换使用带短标签的分段胶囊（或清晰的图标 + 选中态指示），确保新用户无需悬停即可分辨当前所在页面与入口语义。

## 3. 筛选栏与卡片布局（`App.tsx` / `StatCard.tsx` / `AgentCard.tsx`）

- **单行悬浮胶囊原则（目标规范）**：
  - 主页下方已有 `AgentCard` 网格承担快捷点选 Agent 的职责，顶部 `filter-bar` **不再重复铺两行 8 个 Agent 药丸**。
  - 顶部筛选区保持 `w-fit` 轻悬浮形态，左侧用紧凑的 `SelectMenu` 选择 Agent，右侧接日期预设（`今日 / 近7天 / 近30天 / 本月 / 全部 / 自定义`），压成单行，尽量少遮挡主题背景。
- **核心数值防跳动**：
  - 所有数字（Token、百分比、金额、速度、倒计时、表格数字列）**必须带 `tabular-nums`**。
  - 后台轮询或 `usage://updated` 静默刷新时**原地替换数据**，禁止先清空回退为 `Skeleton`（仅首次加载或筛选条件主动切换时显示骨架态）。
- **Hero 与指标卡（`StatCard`）**：
  - 保持「主总量 + 环比差额 + 缓存命中率条 + 6 项 `MiniStat`」结构。
  - 选中单个 Agent 时，右上角保留 `该 Agent 全部时间累计` 与 `平均速度 tok/s` / `平均首字`。

## 4. 图表与数据展示（`TrendChart.tsx` / `ModelPie.tsx` / `HourProfile.tsx`）

- **并排双图等高对齐（重构规范）**：
  - `TrendChart` 与 `ModelPie` 并排时高度保持一致，不得在点选模型后把右侧卡片往下撑开导致左侧留出一大块空背景。
  - **卡内原位切换**：在 `ModelPie` 点选某个模型扇区/图例后，**直接在右侧原图例区原位切换为该模型明细**，顶部保留轻量的 `← 全部模型` 返回按钮与 `命中率`，下方完整展示 **`平均速度 (tok/s)`、`平均首字`** 及 6 格指标（`输入 / 输出 / 缓存读 / 缓存写 / 请求 / 成本`）。
  - 图表切换控件保持完整：未选定具体模型时 `TrendChart` 右上角保留 `[Agent | 模型]` 与 `[面积 | 柱状]`；选定模型后隐藏 `[Agent | 模型]`、保留 `[面积 | 柱状]` 与底部图例。
- **标题与副标题克制**：
  - 卡片标题栏的说明文案保持单行简练（例如 `使用时段 · 按 24 小时汇总（只看形状）`），长篇解释（如采样口径、精度说明）放进 hover `title` 或轻提示气泡，不让副标题在 `860px` 窄屏折行。
- **图表配色**：一律通过 `useTheme()` 读取 `agentColor` 与 `chartPalette`，严禁在图表组件里写死十六进制色值。

## 5. 额度页与多池布局（`Limits.tsx`）

- **全局 4 列统一纵线（`LIMIT_ROW_GRID`）**：
  - 整页卡片共用同一套列宽定义：`[手柄 | 账号列(12rem) | 第1列 | 第2列 | 第3列]`，保证不同 Provider 的进度条左右边缘上下贯穿对齐。
- **多模型池 Provider（如 Antigravity）规范（E1 紧凑对齐方案）**：
  - **禁止额外嵌套池名列**：不得在右侧 3 列内部再塞一列 `9rem` 池名导致进度条变窄、和上方行错位。
  - **禁止落单窗口拉满两列**：单窗口（如只有 `每周` 的 Argon）不得使用 `col-span-2` 拉成两倍长的巨长条。
  - **一列一池 + 条上写重置时间**：左侧保持纯净的 `AccountTitle`（不加多余说明废话）；右侧 3 个模型池直接各占全局 3 列中的 1 列，池内每条进度条上方单行直接展示 `周期 · 重置倒计时`（如 `5h · 5 小时后重置`）与百分比，去掉条下方的额外脚注行，从而在不隐藏重置时间的前提下把卡片高度压到接近常规行、消除左列大块留白。
- **空值防护**：`usedPercent` 为 `null` 时**不画 0% 空进度条**（显示 `--` 占位），避免用户误以为额度已用尽。

## 6. 设置页、弹窗与滚动条（`Settings.tsx` / `index.css`）

- **禁用系统原生弹窗（重构规范）**：
  - 严禁新增 `window.alert`、`window.confirm`、`window.prompt`。
  - 危险操作确认（如全量重扫、删除自定义 Agent、覆盖手动定价）统一使用主题化的自绘确认弹窗；校验提示使用内联提示或主题化 Toast。
- **自绘下拉控件**：所有下拉选择统一复用 `SelectMenu`（`createPortal` 挂载到 `document.body`），禁止回退为无法随主题换肤的原生 `<select>`。
- **设置页分栏拆分（重构规范）**：
  - 避免把所有设置项塞进单文件垂直平铺（`Settings.tsx` 已超 2000 行）。按功能域拆分为左侧分类导航 + 独立子面板组件：`外观与通用`、`数据源`、`自定义 Agent`、`成本定价`、`额度来源`、`版本与缓存`。
- **局部滚动条可见性**：
  - 不应全局隐藏所有元素的滚动条；对于横向宽表（`SessionTable`、成本定价表）与长列表，保留极细、低对比度的自定义滚动条，确保鼠标用户可感知滚动方向。

## 7. 主题与样式硬性红线（与 `theme_interface.md` 联动）

新增或修改任何组件时，必须同时满足以下检查：

1. **禁止硬编码颜色**：不使用 `text-emerald-500`、`bg-white`、`hover:bg-black/5` 等固定色；文字状态色用 `*-text` / `*-label`，填充用 `success` / `warning` / `danger`，hover 叠加用 `hover:bg-overlay/5`。
2. **禁止任意字号与行高**：不得写 `text-[13px]`、`leading-[1.2]` 等脱离 `tailwind.config.js` 倍率体系的任意值，否则主题的 `--otr-font-scale` / `--otr-line-scale` 会失效。
3. **打齐语义钩子**：所有卡片、按钮、分段控件、表格、输入框、进度条、空状态必须保留或正确标注 `data-theme-part` 与 `data-theme-state="selected"`。新增钩子须同步更新 `src/theme/css.ts`、`docs/theme.schema.json` 与 `docs/theme_interface.md`。
4. **提交前必跑校验**：
   ```bash
   npm run typecheck
   npm run test:theme
   npm run test:quota-groups
   ```
